# Skills 支持设计草稿

> Status: Non-authoritative design draft
> Date: 2026-11-12
> Review: 2026-11-13 owner 复审通过；通过对象为本设计草稿，不代表授权实现或 Spike。
> Scope: 统一 Skill 文件库、默认与按 Agent 类型选择、动态发现、Settings 管理，以及主 Agent / Subagent 的自动和显式使用。
> 本文整理已讨论的设计方向，不授权实现或 Spike，不修改现有架构、规格及配置契约。具体交付仍遵循 [Development Workflow](../governance/development-workflow.md)。

## 1. 目标与原则

用户可以自行开发或放入第三方 Skills，在 Settings 中选择哪些可用，由主 Agent 和 Subagent 按需使用。不要求手改配置文件，也不要求重启 Agent。

核心原则：

- 一份文件库，不为每类 Agent 复制 Skill。
- 默认集合加按类型覆盖，不做复杂的叠加规则。
- 目录元数据先进入模型上下文，正文按需加载。
- 自动选择和显式指定共用一个加载工具。
- 显式指定由 LLM 识别，不为 slash 入口新增宿主预展开机制或消息协议。
- Skill 是指令与资源包，不是新的执行引擎，也不自动授予工具权限。

外部依据见 [主流 Agent Skills 实现机制调研](mainstream-agent-skills-implementation-research-2026-11-12.md)。借鉴其机制，不照搬厂商专用消息片段、编辑器附件、远程分发或复杂工作流能力。

## 2. 文件存储

唯一固定发现根为现有 Agent Home 下的 `skills`：

```text
<agent home>\
  skills\
    builtin\
      skill-creator\
        SKILL.md
    code-review\
      SKILL.md
      references\
    documentation\
      SKILL.md
      scripts\
```

- 所有 Agent 类型共用这个根目录。
- 支持分类目录嵌套，从根目录向下发现 `SKILL.md`；找到后，其所在目录即为一个 Skill，不再向该目录内部继续发现其他 Skills。
- 分类目录不参与 Skill 名称，也不赋予优先级、权限或启用状态；例如 `builtin` 只是普通分类名。上例仅说明布局，不表示已决定随附 `skill-creator`。
- 不同分类下的 Skill 名称仍需唯一；冲突时明确报告，不按扫描顺序覆盖。
- 存储可嵌套，使用保持扁平：Skill 列表、模型目录、加载工具和配置选择均按唯一名称处理。Settings 使用普通列表，保留相对于发现根的来源目录；不引入目录级启用、层级继承或覆盖规则。
- 不新增 workspace 概念，不引入每类 Agent 的独立 Home。
- 先支持用户直接放置 Skill 目录；下载器、Marketplace 和自动更新不属于基础范围。
- 以 [Agent Skills 标准](https://agentskills.io/specification) 的 `SKILL.md`、名称、描述和 Markdown 正文为基础；附属资源按需访问。
- 基础范围不承诺兼容所有厂商 frontmatter 扩展。

这里的 Agent 类型指 my-agent 现有的具名 Agent 定义 / 选择，不是模型类型，也不是每次创建的临时 Child 执行实例。现有身份边界参见 [Agent Management](../specifications/agent-management.md)。

## 3. 默认集合与按类型覆盖

文件是否存在、某个 Agent 是否可以使用它，是两件事。

| 配置状态 | 有效集合 |
|---|---|
| 某类 Agent 未配置 Skills | 使用默认集合 |
| 某类 Agent 显式配置 Skills | 完全替换默认集合，不叠加 |
| 某类 Agent 配置空集合 | 不使用任何 Skill |

例如默认集合为 `code-review`、`documentation`：

- 未配置覆盖的 Agent 可以使用两者。
- reviewer 覆盖为 `code-review` 时，只能使用它。
- reviewer 覆盖为空时，两者都不能使用。

这些规则对 Root 和 Child 一致，使用所选 Agent 类型的有效配置，而不是自动复制父 Agent 的类型覆盖。

新发现的 Skill 只进入可选列表，**不自动加入默认集合或类型覆盖**。

本草稿不额外增加第二层全局禁用开关。若希望所有类型都不能使用某 Skill，需要从默认集合和显式引用它的类型集合中移除；不能把“从默认集合移除”误读为自动否定所有类型覆盖。

配置字段名、存储形状与 Settings 保存契约需要在交付设计中结合现有 [Configuration](../architecture/configuration.md) 确定；本文不声称现有配置已支持这些字段。

## 4. Settings 交互

提供用户可操作的入口，而不是只提供配置文件说明：

- 展示已发现 Skill 的名称、描述、来源目录和可用状态。
- 编辑默认 Skills 集合。
- 对每类 Agent 提供“继承默认”或“自定义集合”；自定义集合可为空。
- 明确展示继承状态与当前有效选择，避免空集合和未配置混淆。
- 自动更新新增、修改、删除后的列表；加载或解析错误有可见反馈。
- 程序负责持久化用户的选择，不要求用户手动编辑 JSON。

不预设独立应用商店、复杂 Agent × Skill 矩阵或新的 Agent 管理体系。页面位置与控件布局在后续设计中确定。

## 5. 动态发现和生效边界

### 5.1 用户可见行为

- 自动发现根目录下 Skill 的新增、修改和删除，包括启动时尚不存在、运行中才创建的根目录。
- 不要求手动刷新或重启 Agent。
- Settings 自动反映目录变化；新发现不等于启用。
- 保存默认集合或类型覆盖后，新 Turn 使用最新选择。
- 每个新 Root / Child Turn 使用当时最新的目录与有效集合，即使 Parent Turn 早于本次配置变化。
- 正在执行的 Turn 不因目录或配置变化而中途切换其有效集合。

### 5.2 实现约束

文件监视、定期检查或其他简单可靠的组合都是候选，不在本草稿中指定复杂服务结构。

仅在新 Turn 扫描可以保证执行时更新，但不能独自满足“没有新 Turn 时，打开的 Settings 也自动反映变化”；具体机制需要同时覆盖两个观察面。

有效集合按 Turn 捕获，不代表 Skill 文件也被冻结。使用 Skill 时，通过加载工具获取当前内容，以实际加载和后续工具执行的结果为准。目录是发现提示，不承诺与加载时正文或附属资源构成同一版本快照。

文件读取、缓存及更新检测属于宿主实现选择；prompt builder 消费发现结果并生成 section，不承担文件监视职责。不为 Skills 新增整包快照、已加载状态或缓存一致性协议。

已删除或不可读取的 Skill 不得继续以可用条目广告。配置中对缺失 Skill 的引用应明确展示，不静默清除用户选择或替换成其他 Skill。

## 6. 模型可见目录

在 system prompt 中统一生成 Skills section，包含当前 Agent 有效且可加载的 Skill：

```text
Available skills:
- code-review: 检查代码正确性与回归风险。
- documentation: 编写和维护项目文档。

使用 Skill 前，先调用 Skill 加载工具读取其完整指令。
以本次实际加载的内容为准，历史正文不代替获取当前指令。
用户或委派任务已指定 Skill 时，按指定名称加载，不再自行判断是否匹配。
```

- 初始只提供名称、描述及必要定位信息，不预加载全部正文和资源。
- 目录由公共 prompt 构建逻辑生成，不手工维护每份 Agent 指令。
- Root 和 Child 使用同一机制；子代理不必继承主对话中已经加载的正文。
- 目录不是授权边界：加载工具仍需校验当前执行身份和有效集合。

加载工具是否可见沿用现有 Tool policy 投影；不可见时不广告可调用的 Skills。禁用、审批和拒绝等沿用既有工具处理，不新增 Skill 专属权限状态或 Settings 诊断体系。

现有 [Prompt Composition](../architecture/prompt.md) 区分 prompt 模式、模型上下文与持久化用户消息。新增 section 在不同 prompt 模式下的行为，以及目录过大时的预算与可见错误，需要在交付时明确，不能直接绕过现有契约。

## 7. 自动与显式使用

### 7.1 自动选择

```text
用户提出任务
→ LLM 根据请求及 Skill 名称 / 描述选择
→ 调用加载工具
→ 工具校验并返回正文、资源基准目录
→ LLM 按指令调用既有工具完成任务
```

### 7.2 显式指定

用户可以表达：

```text
/skill code-review 检查这次修改
```

该写法作为模型理解的提示约定，不是宿主必须解析的特殊协议：

```text
原始用户输入进入正常对话
→ LLM 识别已指定的 Skill 和任务参数
→ 调用同一个加载工具
→ 校验、加载并继续执行
```

不增加 slash 专用执行器，不要求 UI 携带 URI 附件，不由宿主先把正文拼进 user prompt，也不新增专门的 Skill 消息类型。正文通过普通工具结果进入当前模型上下文；结果持久化复用既有工具机制。

参数先作为任务文本由模型理解，不引入 shell 插值、位置参数模板或动态命令预执行。命令拼写与补全体验不影响这一基本机制。

### 7.3 Subagent

- 自动使用：Subagent 根据自己的任务和可见目录选择。
- 显式使用：委派任务要求“使用 `code-review` Skill 检查这些修改”，由 Subagent 调用同一加载工具。
- 不要求新增结构化 Skill 委派参数，也不要求复制父 Agent 已加载的全部正文。
- 主 Agent 在委派时应保留用户指定的 Skill 要求，不能只转述任务而丢失指定条件。

本设计选择的是模型驱动调用，不承诺像宿主强制展开一样完全确定。需要通过实际模型验证指定名称、参数传递与先加载再执行的遵循情况，而不是仅以 prompt 中存在一句规则作为验收。

## 8. 加载校验、权限与失败

加载工具使用当前 Turn 的执行身份和有效集合，不能信任模型自行声明的 Agent 类型或任意文件路径。

| 情况 | 行为 |
|---|---|
| Skill 存在且在有效集合中 | 返回正文与资源基准目录 |
| 没有类型覆盖，但默认集合包含它 | 正常加载，不要求再单独启用 |
| 覆盖集合不包含它，或集合为空 | 明确返回当前 Agent 未启用 |
| 名称不存在、冲突或文件无效 | 明确说明问题，不猜测替代项 |
| 文件不可读 | 明确失败，不返回成功形状的空正文 |

显式指定失败后，不自动启用，不静默降级成普通执行。Subagent 应向委派方反馈原因，主 Agent 向用户反馈，不反复委派重试同一个不可用 Skill。

第三方 Skill 正文是指令内容，不具有提升系统权限的效力。加载不执行脚本、不安装依赖、不自动预批准工具；后续文件、进程和其他操作仍受现有工具权限约束。资源基准目录用于正确解释相对路径，不是新的访问授权。

附属资源经现有工具访问实时文件，遵循其默认权限和错误处理。资源变化或缺失不引入 Skill 专属检查，不承诺正文与资源的整包版本一致性。

脚本所需解释器、依赖、环境变量及运行方式由 Skill 自身说明和处理，Agent 按指令通过既有工具执行。my-agent 不为 Skills 新增环境探测、虚拟环境管理、依赖安装器或专属 env 配置。安装、环境准备及执行仍遵循现有工具权限；环境不足或准备失败按默认机制反馈，不因使用 Skill 而绕过限制。

动态禁用影响后续 Turn 的目录和加载资格，不清除已进入对话历史的正文，也不撤销已有工具权限或强制停止当前 Turn。

## 9. 不纳入基础范围

- 每类 Agent 独立 Home、项目 workspace、多来源优先级与兼容目录集合。
- Marketplace、远程 Skill 源、下载 / 更新 / 卸载管理器。
- Skill 专用模型、hooks、动态 shell、依赖自动安装和环境注入。
- Skill 自带工具授权或独立执行引擎。
- 专属消息协议、结构化附件和宿主 slash 预展开。
- 在没有实际规模问题前加入向量检索或复杂路由。

直接发送库外目录临时使用 Skill 不在本次范围内，不能据此绕过固定根目录与有效集合。

## 10. 后续需落实的细节与验证

进入实现前，需要结合源码确定，而不是扩大为额外产品能力：

1. 最小发现布局、名称与目录关系、重名处理、解析校验和路径 / 链接边界。
2. 具体 Settings 字段与保存方式、自动发现时效、有效集合的 Turn 捕获与文件更新检测。
3. 加载工具契约、prompt 模式处理、目录和正文预算。

最小验收应覆盖：

- 多层分类目录中的 Skill 可被发现，分类路径不改变 Skill 名称。
- 找到 `SKILL.md` 后停止向其所在目录内部发现，即使该文件无效，也不把内部示例识别为独立 Skill。
- 不同分类中的同名 Skill 明确报告冲突，加载不任意选择其中一个；其他无冲突 Skill 仍可使用。
- 默认继承、完全替换、显式空集合，Root / Child 规则一致。
- 新增不自动启用；新增 / 修改 / 删除和首次创建根目录无需重启即可发现。
- Settings 在没有新 Turn 时也能自动更新；保存后新 Turn 生效，旧 Turn 不切换。
- 自动选择与显式指定都实际调用加载工具，正文不在初始目录中。
- 主 Agent 向 Subagent 保留指定 Skill，Child 在自己的有效集合内加载。
- 使用时通过加载工具获取当前指令，不以历史正文代替；文件变化后不要求重启，也不要求构成整包同版快照。
- 未启用、不存在、损坏和读取失败有明确反馈，无静默降级；工具禁用、审批以及资源访问沿用既有默认处理。
- 第三方正文和脚本不能绕过工具权限。
- 原始用户输入与已有消息 / 工具结果持久化行为保持不变。

本文只形成设计讨论基线。后续批准交付时再按工作分类形成必要的 Change 与契约，不因本草稿存在而视为已授权修改运行时。
