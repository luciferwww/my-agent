# Deferred Subagent Evolution

> Status: Deferred — frozen and non-authorizing
> Owner: Project owner
> Activation: A future accepted post-Foundation Plan/Specification must explicitly supersede this input

## Retained direction

This input preserves bounded options for evolving the blocking Subagent-as-Tool model toward manager-coordinated fan-out/fan-in. Any successor should retain real Parent identity, Runtime-owned tree/generation/Abort lifecycle, isolated Child Sessions/Models, canonical Tool results, bounded resource ownership, and explicit event correlation.

A future design may evaluate bounded sibling parallelism and manager coordination. It must first define admission, cancellation, Usage/error aggregation, event ordering, Session ownership, limits/backpressure, Shutdown convergence, and interaction/approval routing.

## Not authorized

No implementation, detached/background execution, handoff/team semantics, cross-Turn jobs, shared workspace redesign, scheduler, broad concurrency, or direct reuse of obsolete Child paths is authorized. Current blocking behavior remains owned by [Subagent](../specifications/subagent.md) and [Subagent Model Resolution](../specifications/subagent-model-resolution.md).

## Activation gate

Revalidate against current Runtime composition, Tool ordering, Provider limits, and Subagent tests; choose one explicit concurrency model; produce acceptance and rollback criteria; then obtain project-owner acceptance through [Development Workflow](../governance/development-workflow.md).
