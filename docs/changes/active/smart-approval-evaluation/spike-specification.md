# Smart Approval 本地模型评估 Spike Specification

> - **Status:** Draft
> - **Date:** 2026-11-25
> - **Owner:** Project owner
> - **Authorization:** 待 owner 审批；本文不授权下载、安装、推理或改变真实审批
> - **Decision unlocked:** 模型二态/三态、可处理效果范围和继续试验的价值；[Proposed Plan](plan.md)

## Decision question

本地轻量模型能否根据具体调用及可信环境事实，区分可免确认、需要人工、
明确违背给定规则的操作，而不是仅重复 Sandbox 路径许可？
二态与三态输出在误放行、误拒绝、弃权和成本方面如何取舍？

本 Spike 不决定最终风险接受标准，也不证明模型能预测任意程序的全部效果。

## Falsifiable hypotheses

- H1：候选能在 Node 24 中通过现成受支持接口完成实际 CPU 推理，并返回有限结果；
  ONNX 文件存在不意味着现有 Transformers.js 支持其 tokenizer/架构。
- H2：在路径权限相同但操作后果不同的反事实案例中，模型能给出有用差异；
  若均因路径可写就放行，则没有体现所需 Smart 能力。
- H3：三态的额外 deny 类可能提高拒绝辨识，也可能增加误拒绝；
  二态可能更适合转人工。以同一参考集比较，不预先选定。
- H4：加载、延迟、内存、输入长度及中英文表现允许一个有限后续方案；
  不假设公开通用指标可迁移到本项目。

## Scope and non-goals

首轮评估 Exec 与结构化文件修改的合成调用，少量未知工具作为弃权对照。
接口仍以通用 Tool call 为对象，不设计 Exec-only 产品机制。
不修改产品代码/配置、启用 Smart、扩大资源权限、实际批准任何调用、
训练/微调模型、部署后台服务或重跑 OS Sandbox 实验。
不引入 Python/venv/PyTorch、模型转换或自制推理适配器。
CPU 推理是硬要求，不允许 GPU/WebGPU 或云端推理作为替代验证或失败回退。
优先确认简单接入是否成立；不成立即可结束，不为了完成评测搭另一套系统。

## Method

### 1. 候选、版本与环境

| 本轮暂定候选 | 已核实的公开描述 | 固定产物 revision |
| --- | --- | --- |
| `onnx-community/Qwen3-0.6B-ONNX` | Qwen3-0.6B 的社区 ONNX 转换，模型卡标明 Transformers.js；CPU 可行性待验证，不是原始权重 revision | `79346d370dfae34801d26993fda9ae2372900fd0` |

来源：[转换产物模型卡](https://huggingface.co/onnx-community/Qwen3-0.6B-ONNX/blob/79346d370dfae34801d26993fda9ae2372900fd0/README.md)、
[原模型说明](https://huggingface.co/Qwen/Qwen3-0.6B)及
[官方 Node.js 推理文档](https://huggingface.co/docs/transformers.js/en/tutorials/node)。
原模型声明 Apache-2.0；下载前须核对转换产物的许可/归属、实际文件/hash。
不自动跟随模型卡的新版本链接或把原模型许可当作已核实全部转换文件的许可。

GLiClass 仍可作为原研究的参考，但本轮不执行，也不移植其推理流程；
将来有现成、简洁的 Node 接口时再考虑，不同时维护两套本地模型加载逻辑。

使用现有 Node 24 和临时 Node 项目中的现成 `@huggingface/transformers` 接口；
先固定并记录支持 Qwen3 的包版本和实际 Node CPU 产物，不升级项目现有
`@xenova/transformers`。明确选择 CPU 设备/执行后端，记录实际运行的
后端/执行 provider、模型/分词文件/hash、包版本、CPU/内存与 OS。
模型卡的 WebGPU 示例不满足本实验；仅加载权重或声明 CPU 选项也不替代
实际 CPU 推理。完整二态/三态与性能评测均须在 CPU 上完成。
若库不支持、许可不明、须新增运行时/服务/模型或大量手工适配，停止报告，
不自行导出模型、不改张量流程、不切到 Python。
不启用 `trust_remote_code`、未知 pickle 或自动运行下载仓库脚本。
选择 ONNX/量化产物时记录具体文件，不把不同精度结果混为同一配置。

模型准备阶段只允许获取上述公开 revision 与受支持的推理依赖；
记录实际下载大小和路径。推理阶段使用本地文件/离线选项，不调用在线评估 API。
只加载这个候选并串行 CPU 推理，不启用 GPU/WebGPU，不改宿主权限/全局环境。

### 2. 输入、临时参考与比较

每个案例包含工具/有效参数、明确提供的任务约束、资源权限和已知/未知事实。
任务相关性、Agent 自称有备份或高置信度都不能充当安全证据。
“资源匹配通过”不自动转成“可以免确认”；任意脚本的完整访问不明时保留未知。

最多 24 个基础案例：8 个用于格式/提示校准，16 个保留用于报告。
反事实对与同模板案例放在同一分区；不得用报告集反复改提示再报原成绩。
覆盖局部/大范围写入、覆盖与新建、删除与恢复事实、外发敏感性、动态脚本、
明确禁止事项、未知工具以及中英文上下文。只提供合成数据，不读取真实
项目/凭据来补标签，也不执行命令以“证明”其效果。

执行前按一份短评估 rubric 冻结人工参考：`auto_approve / review / reject`。
`reject` 仅用于本案例明确给定的禁止事项；仅有风险或关键事实不足用 `review`。
这是实验参考，不是新增产品拒绝规则。争议案例单列，不由候选模型自标真值，
不把用户历史点击 Allow 或“执行没出事故”当标签。

比较两种结果格式：

| 格式 | 候选输出 | Shadow 映射 |
| --- | --- | --- |
| 二态 | `auto_approve / needs_review` | 批准候选 / 转人工候选；参考 review 与 reject 都不应自动批准 |
| 三态 | `allow / review / deny` | 批准候选 / 转人工候选 / 拒绝候选；重点检查 deny 是否误拒了可确认操作 |

所有输出只保存为评估数据，不触发实际 approved/rejected 操作。
明确工具 deny/已知资源违规的组合门禁单独测试：不调用模型，且无任何模型
结果可覆盖它。此类门禁不混入模型准确率以虚增效果。
当前真正由 Tool permission 放行的调用不需模型；Exec 命中 tools.allow
仍按当前必审语义作为待评估对照。门禁和全部转人工基线只评价组合正确性/价值。

关闭 thinking、固定并记录生成参数、最多 64 输出 token；
只接受约定的有限标签结果，不编造模型未提供的概率，也不把自报分数当作安全证明。
记录每次完整输入的实际 token 数（包含规则/标签）；超过候选预算则显式
记录无法评估，不静默截断后报安全。相同文本与策略下比较，不靠不同上下文
假装格式优劣；需要额外上下文才能正确判断时报告该限制。

### 3. 计数、性能与失败

推理总上限 60 次，包含一个候选/两格式/校准/重测，不因结果不好无限调参。
每次评估最长 30 秒，单候选冷加载最长 5 分钟；这些是实验停止预算，
不是产品的延迟要求。若接口不能可靠中断，使用一个临时 Node 子进程
运行评估脚本，按确切 owned PID 终止并确认退出。
它只用于实验生命周期控制，不是常驻服务、线程池或产品 Worker 框架，
也不提供能力隔离；不批量杀进程或静默继续。

记录逐例 reference/输出/分数/有效性、模型与提示版本、输入长度，
冷加载、warm 延迟、P50/P95、进程内存与错误/超时。重复观察需计入总预算。
不得把格式失败、输入超限、异常或超时映射为批准；单列为 review/error。

输出原始混淆计数及按后果类型分组的：
误放行、三态误拒绝、自动处理覆盖率、转人工/弃权率和性能。
计数分母说明实际已评估与争议/失败案例；失败不得从可用性报告消失。
少量样本零误放行不构成安全保证，不拟合产品放行阈值或发布准确率承诺。

## Required evidence

| ID | 场景 | 必须观察 |
| --- | --- | --- |
| SAE-E1 | Node CPU 推理与输出协议 | 固定产物完成实际 CPU 推理及所选执行后端证据；无法运行的具体原因；不以 GPU 结果或仅加载成功代替 |
| SAE-E2 | 相同资源权限、不同后果 | 新建/覆盖或局部/广泛操作可得到不同评估；反例也完整保留 |
| SAE-E3 | 禁止事项、外发与未知事实 | 不因“符合任务”或 Agent 自称安全批准；明确拒绝与需人工不混同 |
| SAE-E4 | 格式/上下文/语言比较 | 同一参考集的二态/三态混淆计数、误拒绝与中英文/长输入限制 |
| SAE-E5 | 硬门禁与规则放行 | 单独验证无需模型的情况；真实执行数始终为零 |
| SAE-E6 | 成本、异常与停止 | 实际延迟/内存、错误与预算；超时不批准，临时评估进程可退出，无残留服务 |

## Success, failure, and stop conditions

- 实验完成：有可复现版本、完整计数/失败记录和可解释结论，不等于模型合格。
- 候选继续的必要条件：Node.js 的实际 CPU 推理成功；CPU 不支持或成本
  不可接受时报告失败/不适用，不转用 GPU、云模型或其它运行时补救。
- 可继续候选：至少在保留集体现比“全部转人工”更多的有依据放行；
  若存在明确禁止/高损害误放行，必须展示，不宣称已可上线。
- 全部转人工、仅复述路径权限、输出不稳定、无法加载或资源不可接受，
  均可形成“当前方案不适用/需更多证据”的有效结果。
- 接入/维护复杂度不符合轻量用户友好特性的定位时，直接建议不采用；
  不以增加另一套模型运行时或服务来补救。
- 达到预算、需安装范围外工具/模型、出现敏感输入或临时评估进程无法清理时停止。
  不以云模型兜底、不增加试验规模、不掩盖失败。
- 输出格式、风险接受标准和实际放行范围由 owner 根据结果再定；
  不因通用 benchmark 或这次零误放行自动进入产品实现。

## Constraints and safety

样本是文本/结构化数据，不是真实工具执行指令。评估脚本不接入真实工具
执行器，不对样本或模型输出进行 eval、Shell 或动态代码执行。
临时评估进程只用于超时终止，不宣称撤销了普通 Node 进程的文件/子进程能力。
不消费实际会话、截图、用户秘密或真实项目源代码，网络仅用于
获准的模型/依赖准备。不给生产 Agent 添加任何 grant、模型 provider 或模式。
只清理独立实验内确切文件/owned 子进程，不删除已有缓存或修改其它服务。
调用失败显式报告；审批仍由当前产品机制处理。

## Deliverables

获准执行后生成 `spike-results.md`，含版本/案例参考来源、原始计数、代表性
错误、性能与停止证据，说明是否值得继续以及二态/三态的实测取舍。
清理临时评估进程、脚本和 Node 依赖；模型缓存是否保留需在结果中明确。
只将证据支持的结论反馈到[设计草稿](../../../research/smart-approval-design-draft.md)，
不自动接受 ADR/产品 Spec、不提交或推送。
遵循[Development Workflow](../../../governance/development-workflow.md)；
Spike 审批只授权这一有限证据收集。
