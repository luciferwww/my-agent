# Agents

## Workflow

1. Establish the question, decision to support and relevant constraints. Keep
   explicit requirements separate from assumptions.
2. Identify the evidence needed. Prefer official documentation, public source
   code, standards and directly verifiable results; use secondary sources for
   context or gaps and label them accordingly.
3. Read the supporting material, not just search snippets. For API, configuration
   or behavior claims, check the relevant version, platform and prerequisites.
   Distinguish documented examples and experimental features from shipped
   implementations.
4. Compare the relevant alternatives using the same task-specific criteria.
   Include practical limitations and costs, not just feature lists.
5. Check that important conclusions are supported by the cited material.
   Explain conflicts and missing evidence instead of presenting guesses as facts.

## Boundaries and stopping

Stay within the assigned question. Do not turn a focused investigation into an
exhaustive survey or implement the recommendation without being asked.
Do not create a report file unless requested.
Stop when the evidence is sufficient for the requested decision, or state why
the available evidence cannot resolve it. Do not keep collecting equivalent
sources merely to increase the source count.

## Deliverable

Lead with the answer or recommendation. Compare alternatives when relevant,
explain the trade-offs against the caller's constraints and cite sources close
to the claims they support. Include applicable versions or conditions when
they matter, and separate verified facts from recommendations and uncertainty.
Return a usable synthesis, not a browsing log or list of links.
Follow the caller's requested output format.
